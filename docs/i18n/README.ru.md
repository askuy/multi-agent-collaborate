# Trellis

**Общее рабочее пространство, в котором ИИ-агенты распределяют задачи, объединяют изменения и совместно исправляют ошибки.**

[English](../../README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [Deutsch](README.de.md) · **Русский** · [Español](README.es.md) · [한국어](README.ko.md) · [Português](README.pt.md) · [Tiếng Việt](README.vi.md)

Trellis — бэкенд на Rust для нескольких ИИ-агентов, работающих с общим кодом, документами или структурированными данными. Каждый агент работает в своей сессии, а общий сервер хранит историю, интегрирует изменения в `main` и уведомляет агентов, когда меняются данные, от которых зависит их работа.

Доступны **CLI**, **MCP**, **HTTP API** и **Rust-крейты**. Вы предоставляете агентов и среду их выполнения; Trellis обеспечивает общее состояние и координацию.

> **Статус: ранняя стадия разработки.** Реализованы хранение данных, слияние, координация, CLI, серверы HTTP и MCP, интеграция с Git и проверки после интеграции изменений. Опубликованы первые результаты сравнительных тестов. API и рабочие процессы ещё могут меняться.

## Возможности

| Возможность | Для чего нужна |
| --- | --- |
| Общая история | Версионирование наборов изменений с привязкой к агенту, сессии и задаче. |
| Слияние и конфликты | Слияние текста и структурированных изменений JSON/YAML; сохранение неразрешённых конфликтов для исправления агентами. |
| Координация задач | Атомарное получение задач, объявление планируемых изменений и временные аренды для исключительного доступа. |
| Общий контекст | Запись фактов, ошибок, итогов и решений; чтение новых записей и уведомления об изменениях ранее прочитанных данных. |
| Проверки | Запуск настроенных проверок после попадания изменений в `main` и создание задач на исправление ошибок. |
| Совместимость с Git | Импорт снимка Git и экспорт интегрированных наборов изменений в Git-коммиты. |

Обычный цикл: **получить задачу → внести изменения → интегрировать → обработать обратную связь**. Операция *land* просит сервер интегрировать изменения сессии в `main`. Проверки выполняются после этого, поэтому успешная интеграция ещё не означает, что тесты пройдены.

## Быстрый старт

Требуются **Rust 1.85+**, **Cargo** и **Git**. Команды ниже рассчитаны на оболочку, совместимую с Bash.

### 1. Установка

```bash
git clone https://github.com/askuy/multi-agent-collaborate.git
cd multi-agent-collaborate
cargo install --locked --path crates/trellis-cli
```

### 2. Запуск общего сервера

В одном терминале выполните:

```bash
tl serve
```

Адрес по умолчанию — `http://127.0.0.1:7420`. Данные хранятся в `.trellis-data` в рабочем каталоге сервера. Оставьте этот терминал открытым. Все агенты одного репозитория должны подключаться к одному процессу сервера: блокировки для координации хранятся внутри этого процесса.

### 3. Передача изменения между двумя агентами

В другом терминале используйте новый каталог:

```bash
mkdir trellis-demo
cd trellis-demo
export TRELLIS_REPO=demo
tl init

tl --as alice open ./alice
echo "Hello from Alice" > ./alice/notes.md
tl --as alice land ./alice -m "Add a shared note"

tl --as bob open ./bob
cat ./bob/notes.md
```

Теперь рабочая копия Bob содержит `Hello from Alice`. Чтобы продолжить работу после интеграции, откройте следующую сессию командой `tl --as alice next ./alice`. Результаты команд выводятся в JSON. Код завершения `land` равен `2` при конфликте и `3` при отклонении изменений.

Очередь задач, обновления, разрешение конфликтов, политики и валидаторы описаны в [руководстве](../usage.md) на английском языке.

## Подключение агента

| Интерфейс | Точка входа | Типичное применение |
| --- | --- | --- |
| CLI | `tl` | Агенты с доступом к оболочке, ручная работа и скрипты |
| MCP через stdio | `tl mcp` | Агенты с поддержкой MCP |
| HTTP/JSON + SSE | `tl serve` | Приложения на любом языке |
| Rust-крейты | `crates/` | Встраивание в процесс и клиенты на Rust |

Для Claude Code сначала запустите `tl serve` и инициализируйте репозиторий `demo`, затем добавьте в `.mcp.json` проекта:

```json
{
  "mcpServers": {
    "trellis": {
      "command": "tl",
      "args": ["mcp"],
      "env": {
        "TRELLIS_REPO": "demo"
      }
    }
  }
}
```

Задайте каждому агенту отдельный идентификатор, например `TRELLIS_PRINCIPAL=agent-1 claude`. Каждый агент запускает собственный процесс `tl mcp`, подключённый к общему HTTP-серверу. Если адрес сервера отличается от стандартного, задайте `TRELLIS_SERVER`. Инструменты MCP позволяют управлять сессиями, чтением и записью, интеграцией, задачами, конфликтами, уведомлениями и общим контекстом.

## Что показывают сравнительные тесты

В [сравнении от 16 октября 2026 года](../dogfood/2026-10-16-final-comparison.md) каждую конфигурацию запускали трижды с одной моделью, одинаковым уровнем усилий на рассуждение и одинаковыми инструментами агентов. Это небольшие эксперименты, а не универсальная гарантия производительности.

Медианное время до прохождения всех тестов, включая необходимые исправления:

| Конфигурация | 60 задач | Изменение интерфейса |
| --- | --- | --- |
| Один агент | 8:52 | 1:10 |
| Git worktrees, стандартное слияние | 3:52 | 3:21 |
| Git worktrees, слияние union для журнала изменений | 3:14 | 1:51 |
| Trellis, без блокировок | 3:23 | 2:26 |

Время указано в формате «минуты:секунды». В параллельных конфигурациях использовались пять агентов для 60 задач и три для изменения интерфейса. Trellis делал завершённую работу доступной в `main` по ходу выполнения. На независимых задачах Git worktrees со слиянием union для журнала изменений оказались быстрее и дешевле; небольшое изменение интерфейса быстрее всего выполнил один агент. В отчёте также приведены затраты, ход исправлений и результаты Trellis с блокировками.
