# Trellis

**AI エージェントがタスクを分担し、変更をマージし、問題を共に修復するための共有ワークスペース。**

[English](../../README.md) · [简体中文](README.zh-CN.md) · **日本語** · [Deutsch](README.de.md) · [Русский](README.ru.md) · [Español](README.es.md) · [한국어](README.ko.md) · [Português](README.pt.md) · [Tiếng Việt](README.vi.md)

Trellis は、複数の AI エージェントが同じコード、ドキュメント、構造化データを扱うための Rust 製バックエンドです。各エージェントは独立したセッションで作業し、共有サーバーが履歴の保存、`main` への変更の統合、依存する内容が変わった際の通知を担います。

**CLI**、**MCP**、**HTTP API**、**Rust クレート**から利用できます。エージェントと実行環境は利用者が用意し、共有状態と作業の調整は Trellis が提供します。

> **開発状況：初期段階。** 基本的なストレージ、マージ、タスク調整、CLI、HTTP・MCP サーバー、Git 連携、統合後の検証は実装済みです。初期ベンチマークも公開しています。API やワークフローは今後変更される可能性があります。

## 主な機能

| 機能 | できること |
| --- | --- |
| 共有履歴 | 変更セットをバージョン管理し、エージェント、セッション、タスクとの対応を記録します。 |
| マージと競合処理 | テキストや JSON/YAML の構造化された変更をマージし、未解決の競合を修復用に保持します。 |
| タスク調整 | タスクをアトミックに取得し、変更の意図を宣言し、排他アクセスが必要な場合は有効期限付きリースを使います。 |
| 共有コンテキスト | 事実、失敗、要約、決定を記録します。新しい記録だけを読み取り、既読の内容への影響を通知で把握できます。 |
| 検証 | `main` への統合後に設定済みのチェックを実行し、エラーを修復タスクに変換します。 |
| Git 連携 | Git のスナップショットを取り込み、統合済みの変更セットを Git コミットとして書き出します。 |

基本の流れは **タスク取得 → 編集 → 統合 → フィードバックへの対応**です。*land（統合）* は、セッション内の変更を `main` に取り込むようサーバーに要求する操作です。検証は統合後に行われるため、統合の成功だけではテストの成功は保証されません。

## クイックスタート

**Rust 1.85 以上**、**Cargo**、**Git** が必要です。以下のコマンドは Bash 互換のシェルで実行します。

### 1. インストール

```bash
git clone https://github.com/askuy/multi-agent-collaborate.git
cd multi-agent-collaborate
cargo install --locked --path crates/trellis-cli
```

### 2. 共有サーバーを起動

ひとつのターミナルで実行します。

```bash
tl serve
```

既定のアドレスは `http://127.0.0.1:7420` です。データはサーバーの作業ディレクトリ内の `.trellis-data` に保存されます。このターミナルは起動したままにしてください。調整用のロックはプロセス内に保持されるため、同じリポジトリを使う全エージェントは同じサーバープロセスに接続する必要があります。

### 3. ふたつのエージェントで変更を共有

別のターミナルで、新しいディレクトリを使って実行します。

```bash
mkdir trellis-demo
cd trellis-demo
export TRELLIS_REPO=demo
tl init

tl --as alice open ./alice
echo "Hello from Alice" > ./alice/notes.md
tl --as alice land ./alice -m "Add a shared note"

tl --as bob open ./bob
cat ./bob/notes.md
```

Bob の作業コピーに `Hello from Alice` が表示されます。統合後も作業を続ける場合は、`tl --as alice next ./alice` で次のセッションを開きます。コマンドの結果は JSON 形式です。`land` の終了コードは、競合時が `2`、変更の拒否時が `3` です。

タスクキュー、更新、競合解消、ポリシー、検証の詳細は[利用ガイド](../usage.md)（英語）を参照してください。

## エージェントを接続

| インターフェース | 起動方法 | 主な用途 |
| --- | --- | --- |
| CLI | `tl` | シェルを使えるエージェント、手動操作、スクリプト |
| MCP（stdio） | `tl mcp` | MCP 対応エージェント |
| HTTP/JSON + SSE | `tl serve` | 任意の言語によるアプリケーション |
| Rust クレート | `crates/` | プロセス内への組み込み、Rust クライアント |

Claude Code では、`tl serve` を起動して `demo` リポジトリを初期化した後、プロジェクトの `.mcp.json` に次の設定を追加します。

```json
{
  "mcpServers": {
    "trellis": {
      "command": "tl",
      "args": ["mcp"],
      "env": {
        "TRELLIS_REPO": "demo"
      }
    }
  }
}
```

`TRELLIS_PRINCIPAL=agent-1 claude` のように、エージェントごとに異なる識別名を設定してください。各エージェントは個別の `tl mcp` プロセスから共有 HTTP サーバーに接続します。接続先が既定と異なる場合は `TRELLIS_SERVER` を設定します。MCP ツールでセッション、読み書き、統合、タスク、競合、通知、共有コンテキストを操作できます。

## ベンチマークから分かること

[2026 年 10 月 16 日の比較](../dogfood/2026-10-16-final-comparison.md)では、モデル、推論の強度、エージェントのツールをそろえ、各条件を 3 回実行しています。小規模な実験であり、一般的な性能を保証するものではありません。

すべてのテストが通るまでの時間の中央値です。必要な修復時間を含みます。

| 構成 | 60 タスク | インターフェース変更 |
| --- | --- | --- |
| エージェント 1 体 | 8:52 | 1:10 |
| Git worktrees、既定のマージ | 3:52 | 3:21 |
| Git worktrees、変更履歴に union マージ | 3:14 | 1:51 |
| Trellis、ロックなし | 3:23 | 2:26 |

時間は「分:秒」です。並列構成では、60 タスクに 5 体、インターフェース変更に 3 体のエージェントを使いました。Trellis は完了した作業を実行中から順次 `main` に反映します。独立したタスクでは、変更履歴に union マージを使う Git worktrees の方が速く低コストでした。小規模なインターフェース変更では、単一エージェントが最速でした。レポートには費用、修復の挙動、ロックを使った Trellis の結果も掲載しています。
